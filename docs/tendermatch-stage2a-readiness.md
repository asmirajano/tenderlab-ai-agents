## Input, outcome and authority

## Value and confidence semantics

The source registry is authoritative for its recorded statements and identities,
not independent proof that a supplier statement is true. Preserve original claim
status, source field/record/system, external claim ID, artifact ID/hash/availability,
profile and batch identity, retrieval date, full claim hash and source wording.
SOURCE text/amount remains separate from CALCULATED decimal scaling and ESTIMATED
lexical classification. No ASSUMED defaults are used. Unknown is MISSING, not zero.

Mapping completeness, source verification, artifact availability, classification
inference and human review are separate dimensions; do not average them into a
new confidence score. Source text saying Verified never upgrades registry status.
No human approval is generated by an automated audit.

## Shared field rules (both batches)

| Target field | Source evidence and guard |
| --- | --- |
| classification | Exact supported classification claim, or provisional lexical activity/product/role interpretation. Preserve services, consulting, mixed and unresolved outcomes. Do not infer from names, supplier IDs or country. Conflicting scope remains mixed/needs evidence. |
| product_families | Tangible stated products from product families, categories or portfolio; service/process terms remain separate. |
| works_specializations | Explicit works activities, not manufacture of construction machinery/materials. |
| industries_served | Explicit industry claim only; no inference from a customer's name or a product's possible use. |
| materials | Stated materials; combined specifications remain separately retained. |
| manufacturing_processes / service_capabilities | Supported activity and process descriptions; never generic Goods classification evidence by themselves. |
| output_capacity | Explicit production/output quantity and product unit; preserve missing reporting year/time basis. Never order book, employee count, factory area or package dimensions. |
| facilities / workforce / equipment / specifications | Separate quantities and exact measures; preserve ranges, qualifiers, units, explicit years and periods. Ambiguous numbers remain unparsed with a reason. |
| geographic_markets | Stated markets; exclude expo, certification, client-count and inferred-global substitutions. Never infer reach from headquarters. |
| local_presence / delivery / after_sales | Preserve source location, origin/destination and stated service terms separately. No implied local registration or delivery feasibility. |
| certifications | Exact named credential statements only; generic ISO/marketplace badges, distributor labels or inspection services are not a held certificate. Named claims remain unverified unless the source registry says otherwise. |
| comparable_contracts | Must identify a project/contract, role and scope; customer lists, ratings, shipment counts and experience years are not comparable contracts. Preserve insufficient references separately. No contract comparability to a tender is assessed. |
| financial | Separate metric, amount/range, currency, reporting year, cadence and qualifier. Bare `$` has unknown currency; unspecified financial scale has unknown metric; transaction value, backlog and order book are distinct from turnover. Performance percentages go to operating metrics. |
| compliance | Preserve unresolved allegations/testing and missing screening. No clean/compliant inference. |

`MAPPED` means the field's stated semantic value is structurally usable, not
verified. `NEEDS_EVIDENCE` means a candidate or incomplete/ambiguous fact is
retained. `UNKNOWN` means no usable stated value. Missing required monetary
dimensions do not erase the known amount; missing production units do not erase
the source number. Every input claim receives a mapped, needs-evidence or missing
audit entry even if it does not become a Formula operand.

Overall readiness remains `NEEDS_EVIDENCE` when classification is provisional,
required dimensions are absent/ambiguous, or independent evidence/compliance
review is missing. Outside-v1.1 scope is a separate descriptive field, not an
eligibility outcome or exclusion. Formula v1.1 and its weights are unchanged.
Its legacy `capacity` field is not populated by indiscriminately concatenating
the newly typed measures. Candidates retain the target-specific meaning for a
later approved adapter; nothing is wired into scoring now.

## Validation / actual-output ledger

The generated Markdown/JSON report records all 117 supplier outcomes, field
coverage for 100/17/117, exact lineage hashes, idempotence, negative semantics,
and limitations. Synthetic tests cover grammar boundaries and invalid evidence;
the full pinned experiment proves the actual source population was reviewed.

| What happened | Layer / cause | Correction | Reusable rule | Evidence |

| Both source batches use broad, incompatible labels | Semantic mapping: field names used as meaning | One shared semantic mapping with typed measures and explicit uncertainty | Map the claim, not the column name | Full 117-supplier audit plus cross-batch equivalence tests |
| Legacy capacity includes backlog and order book | Domain mapping conflates financial and physical measures | Retain as financial-other; no output-capacity operand | A monetary order pipeline is not production capacity | Negative measure tests and source-linked correction records |
| Neutral financial scale includes dispatch/reorder percentages | Domain mapping conflates operating performance with money | Retain operating metrics; financial remains missing | A number alone does not establish a financial metric | Percentage/rating tests and full replay |
| Market and contract fields contain expo/customer/rating evidence | Semantic inference exceeds supporting evidence | Preserve supporting context without claiming delivery reach or contracts | Presence/popularity is not delivery or comparable experience | Geography/reference negative tests and full replay |

## Reproduction

From the authoritative worktree, with the existing ignored restricted credentials:

```text
node --experimental-strip-types scripts/tendermatch-align-suppliers.mjs plan
node --experimental-strip-types scripts/tendermatch-align-suppliers.mjs capture
node --experimental-strip-types scripts/tendermatch-align-suppliers.mjs run outputs/stage2a/source-<explicit source hash>.json
node --experimental-strip-types scripts/tendermatch-align-suppliers.mjs replay outputs/stage2a/source-<explicit source hash>.json
```

Capture is read-only and fails on drift from accepted Stage 2; it does not adopt a
new batch. Run writes only local immutable content-addressed artifacts and the
safe committed evidence projection. Replay validates cache/output without
rewriting the committed evidence report. No default source path or latest lookup.

machine-readable sibling for identities and full field-level coverage.
